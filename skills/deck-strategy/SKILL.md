# 演示策略与叙事

先建立可验证的叙事，再制作页面。不要从模板或页数开始。

本 Skill 的默认交付物是项目内 Markdown 文档，不是演示文件。除非用户明确要求只在聊天中讨论或不要创建文件，否则使用 `write` 新建 `.md`，或使用 `read` 后再以 `edit` 更新用户指定的现有 Markdown 文件。不得调用 `slides_create`、`slides_write` 或 `slides_export`，不得生成 `.slides.json` 或 `.pptx`。

由 `ppt-production-workflow` 调用时，本 Skill 只完成 Markdown 大纲阶段并更新 `workflow-status.md`。审阅模式标记为 `awaiting-review` 后停止；连续模式通过自检后标记为 `completed` 并交还总控。不得自行读取文案、模板或视觉 Skill，后续阶段由总控决定。

## 输入判断

读取用户引用的材料，提取：

- 受众及其已有认知；
- 演示结束后希望受众做出的决定或行动；
- 场景、时长和必须覆盖的主题；
- 可直接引用的事实、数据和出处；
- 明确约束，例如品牌、页数、语言和截止时间。

如果缺少的信息会改变结论或受众行动，指出缺口并询问。其余缺口可以采用保守假设，但必须显式写出。不得补造事实、数字、客户评价或来源。

## 建立叙事

1. 用一句话写出整份演示的核心承诺：受众看完将理解什么，以及为什么现在需要关注。
2. 将材料区分为事实、解释、建议和待验证项。核心结论必须能追溯到事实或被明确标记为建议。
3. 选择最贴合目标的主线：问题—分析—答案、现状—目标—路径、机会—证据—行动，或确有时间因果时的时间线。不要为了形式套用框架。
4. 先生成逐页地图。每页记录：页面职责、结论式标题、关键证据、合适的视觉表达、内容规模，以及与前后页的连接。
5. 删除不推动主线的页面；把同一页面中的多个独立结论拆开。

## Markdown 产物

先确定本次演示的统一产物目录：用户明确指定目录时使用该目录；用户只指定了交付文件路径时使用其父目录；两者都没有时，根据主题生成简短、安全、可读的项目相对目录，例如 `<topic>-presentation/`。自动名称应移除路径分隔符和控制字符、把连续空白折叠为短横线；主题仍不明确时使用 `presentation-project/`。

Markdown 必须写在该目录中。用户指定文件名时遵循该文件名，但必须以 `.md` 结尾；未指定时使用 `<topic>-deck-strategy.md`。产物目录已存在且属于同一演示任务时复用；存在同名但内容无关的目录或文件时，不得覆盖，改用带递增编号的目录或文件名。

文档至少包含：

1. 演示任务：受众、目的、场景、期望行动和硬性约束；
2. 证据边界：可用事实与来源、推论、建议、待验证项和保守假设；
3. 核心承诺与叙事主线；
4. 标题序列；
5. 逐页地图：页码或顺序、页面职责、结论式标题、关键证据、视觉建议、内容规模、前后连接；
6. 待用户确认的问题，以及这些问题会影响哪些页面或结论。

逐页地图优先使用 Markdown 表格；单元格内容过长、包含多段证据或来源时，改用逐页三级标题，避免为了保持表格而压缩必要限定条件。文档只保存策略和页面规划，不嵌入 `slides_write` 参数、PPTist 完整 JSON、Base64 图片或模板资产。

## 下游交接

Markdown 大纲只描述内容语义，不分配 PPTist 页面角色、模板 ID、候选页索引或节点类型。模板映射属于后续 `pptist-template-library` 阶段；即使用户已经指定模板，也不能让模板结构反向决定核心叙事。

用户明确给出模板、品牌或硬性页数时，在“演示任务”中原样记录为下游约束，并在逐页地图中记录预计条目数量、文字密度或图片需求。不要在本阶段选择具体模板页面，也不要为了适配模板提前删除证据或合并独立结论。

## 完成门槛

- 仅阅读所有页面标题，也能复述完整论证；
- 每个关键结论都有证据或清晰的假设标记；
- 开头建立问题与价值，结尾给出可执行的下一步；
- 页数服从信息结构，而不是先凑目标页数；
- Markdown 文件已写入或更新，路径在最终回复中明确列出；
- Markdown 位于本次演示的统一产物目录中；
- 没有创建或导出 `.slides.json`、`.pptx` 等演示文件。

## 本地依据

叙事流程、逐页组织和 Markdown 交付边界已经固化在本文件中。执行时不需要访问模板或演示渲染相关的网络文档。
