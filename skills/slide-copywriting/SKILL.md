# 幻灯片文案

文案服务于现场理解，不把报告正文原样搬到页面。

由 `ppt-production-workflow` 调用时，本 Skill 只完成逐页文案阶段：把观众可见标题、正文、数据结论、流程文案和来源呈现写入统一目录中的 `<topic>-slide-content.md`，并更新 `workflow-status.md`。审阅模式标记为 `awaiting-review` 后停止；连续模式通过自检后标记为 `completed` 并交还总控。此阶段不得选择模板、调用 `slides_write` 或生成 `.slides.json`；只有工作流进入上游内容稳定的可编辑草稿阶段时，才允许转换为演示元素。

## 写作规则

- 标题表达本页结论或变化，不只写“市场分析”“解决方案”等主题标签。
- 一页承担一个主要认知任务。出现两个需要分别证明的结论时拆页。
- 正文优先使用短句、数字、对比和动词；保留必要限定条件，不能为了简短改变事实含义。
- 并列项必须语法平行、粒度一致。说明文字与行动项分开。
- 数字同时交代口径、时间范围和单位；没有来源的数字不得写成事实。
- 首次出现的专业缩写应解释。避免口号、空泛形容词和同义反复。
- 内容放不下时先删减、归并或拆页，不以极小字号掩盖信息过载。

## 匹配 PPTist 模板

用户要求套用模板时，为文案标记必要的内容角色：页面标题与副标题、正文，以及重复条目的 `itemTitle`、`item`、`itemNumber`；目录或过渡页需要时再标记章节编号。角色用于匹配占位区域，不应出现在最终可见文案中。

模板选择前固定条目数量。条目超过版式容量时拆页，不随意删除限定条件或缩小字号。`slides_write` 接受纯文本而不是 PPTist 的完整富文本 HTML，因此只保留换行和文字含义，并通过工具公开的字段设置样式。文本框还要为 PPTist 默认的左右各 10px 内边距和段落间 5px 间距预留空间。

## 逐页产物

写入演示文稿前，为每页形成：

1. 一句结论式标题；
2. 支撑该结论的最少必要信息；
3. 需要强调的数字或行动；
4. 适合的视觉形式；
5. 仍需用户确认的事实或措辞。

用户要求直接制作时，把文案转换为 `slides_write` 可表达的文本和形状。写入前必须先调用 `slides_read` 获得最新修订号；编辑既有文件时必须保留未要求删除的页面和内容。

## 自检

- 标题序列是否单独构成连贯故事；
- 正文是否真正证明标题，而非重复标题；
- 是否存在无法追溯的事实、数字或引用；
- 同一概念、单位、时态和专有名词是否一致；
- 是否有可以移到口头表达、而无需留在页面上的内容。

## 本地依据

结构化写作、模板节点角色和文本边界已经固化在本文件中。执行时不需要访问 PPT Master、Marp、Slidev 或 PPTist 的网络文档，也不调用其脚本。
