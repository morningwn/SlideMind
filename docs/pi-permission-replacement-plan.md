# Pi 权限系统替换实施提案

日期：2026-09-16。

状态：待确认实施。本文细化 [Pi Agent 配置统一管理方案](pi-managed-configuration-plan.md) 中的权限系统选型；尚未修改运行时代码，也未完成运行时安全等价验证。

## 决策

将 `pi-permission-system` 替换为 SlideMind 主进程管理的固定权限能力，但不复刻第三方扩展的多层策略文件、终端授权弹窗、会话授权记忆、子 Agent 转发和 MCP/Bash 规则引擎。Pi SDK 继续负责模型调用、会话和工具循环。权限能力由会话工具白名单、每个工具的执行边界和少量默认拒绝检查组成。

替换按阶段进行。在新旧机制共同运行并通过下述验收前，不移除现有扩展。若固定能力无法覆盖实际产品需求，应保留固定版本扩展并对全部外部配置读取入口打补丁；不得用一个只检查工具名的扩展冒充等价替代。

## 目标、范围与威胁模型

- 目标：模型发起的工具调用只能使用应用注册的能力；文件操作只能触达当前项目内允许的文件，或应用明确提供的只读内置 Skill；项目和用户目录不能改变权限策略。项目句柄、文件路径和工具参数都由主进程校验。
- 产品现状不需要 Shell、PowerShell、MCP、动态授权弹窗、用户自定义权限规则或子 Agent 权限转发。不要为兼容这些未启用能力增加实现。
- 默认拒绝未知工具；新增工具须声明资源类别、可访问范围和执行层校验。`tool_call` 钩子可用于及早拒绝和记录结果，但不能代替工具执行处的校验。
- 本方案约束模型工具调用以及应用接管的代码路径。Pi 与被显式加载的第三方扩展仍运行在 Electron 主进程权限下；`pi-web-access` 的内部文件和网络访问不受本权限层约束。若产品要求运行不可信扩展或抵御本机并发篡改文件树，需另外设计进程或操作系统级隔离，不能宣称本方案提供沙箱。
- 用户明确要求阅读项目内文档时，按文件工具权限处理；禁止的是自动加载外部配置，不是把所有 `.pi/` 路径解释为用户不可阅读。凭据与应用私有数据应按实际存放路径单独保护。

## 当前风险基线

1. 应用通过 `preparePermissionSystem` 写入策略，并用进程环境变量向插件指定目录；插件仍会构造并读取项目 `.pi/agent/` 权限层，与统一配置目标冲突。
2. 当前权限测试只检查词法上的项目内外路径和 Skill 写入。插件的路径比较不解析符号链接；Pi 的 `read`、`grep`、`find`、`ls` 和应用包装的 `write`、`edit` 最终执行链须分别验证。版本记录服务只追踪文件变更，不承担文件授权。
3. `createAgentSession` 目前未传入内存 `SettingsManager`，资源加载器仍列出应用目录及项目 `.pi/skills`。权限替换不能被误报为 Pi 核心和其他扩展的配置隔离完成。
4. 以上属于源码审查结论和失效假设。须在隔离临时目录中以实际工具调用验证，不能仅凭静态推断宣称已存在可利用漏洞。

## 受控策略

| 工具类别                                                   | 允许范围                                            | 执行处约束                                                                                                           |
| ---------------------------------------------------------- | --------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `read`                                                     | 当前项目普通文件；应用显式列出的内置 Skill 只读目录 | 相对路径以项目为根；绝对路径仅在允许根内有效。拒绝越界、符号链接、受保护目录和凭据文件；保留文本截断与图片读取行为。 |
| `write`、`edit`                                            | 当前项目中允许修改的普通文件                        | 绝对路径仅在项目内有效；拒绝越界、符号链接、只读 Skill 和受保护目录；检查现有目标与父目录；保留版本记录与变更事件。  |
| `grep`、`find`、`ls`                                       | 当前项目中允许枚举的目录和文件                      | 缺省路径为项目根；搜索与枚举不得跟随符号链接或越过受保护目录。`grep` 的内容读取也须受同一文件策略约束。              |
| `todo`、`template_query`                                   | 会话清单、应用内置模板                              | 维持各自参数校验；不授予通用文件访问。                                                                               |
| `document_read`、`pptx_read`、`slides_*`、`download_asset` | 当前项目；另有模板、下载和导出专用约束              | 继续在服务层校验项目句柄、文件路径、revision、下载地址或导出目标；逐项核对是否存在插件原先未覆盖的参数路径。         |
| Web 工具                                                   | 由后续 Web Access 方案决定                          | 权限层只控制工具是否注册。网络目标、重定向、凭据、缓存和文件读取由 Web 能力自身负责。                                |
| Shell、PowerShell、MCP、未知工具                           | 不注册                                              | 会话白名单和注册表断言均拒绝；重载后重新验证。                                                                       |

受保护目录的首版清单至少包含 `.git`、`.slidemind`、`node_modules`、`out`、`coverage` 和 `release-dist`；读、写和搜索均跳过这些目录，写入另外拒绝项目 `.pi/` 配置目录。默认拒绝模型读取 `.env`、`.env.*`、私钥和经清单确认的凭据文件，搜索也不得返回这些内容。该清单不能替代用户对项目资料敏感性的判断；如产品确需读取其中某类文件，另行设计明确的受控授权，不把默认策略放宽为允许。

## 实现边界

1. **会话入口**：使用 Pi 0.85.1 的 `createAgentSession({ tools })` 显式白名单，并在资源重载及会话恢复后检查工具注册表和实际活动工具。`noExtensions` 只关闭自动发现，显式注册的第三方扩展仍需单独审计。继续不注册 Shell、PowerShell、MCP。工具名相同的扩展可能覆盖 Pi 内置实现，因此同时断言工具来源与预期注册数量。
2. **会话策略快照**：在主进程按项目句柄取得规范化项目根目录，连同内置 Skill 根目录构造不可变的会话策略对象，经内部 `ExtensionFactory` 或工具构造函数注入。配置来自应用代码及应用设置，不从环境变量、用户 Pi 目录或项目 `.pi/agent` 回退。会话重建读取新的应用配置快照，进行中的工具调用使用其创建时快照。
3. **文件边界**：集中实现路径分类与边界判断，但最终校验必须位于执行文件操作的代码路径。已存在目标逐段检查 `lstat` 并确认真实目标仍处于允许根；新目标检查所有已存在父目录和最终目标。拒绝符号链接，包括指向项目内部的链接，避免不同工具采用不同解释。不能用字符串前缀或 `ProjectMutationService` 的版本路径归一化充当授权。确认检查后实际 I/O 的竞态边界，并在文档中限定所能保证的威胁模型；如需抵御并发恶意替换目录，升级为系统级隔离。
4. **文件工具接管**：`read`、`write`、`edit` 使用受控实现覆盖同名 Pi 工具，尽量复用 Pi 的参数契约、截断、图片结果和版本事件。`grep`、`find`、`ls` 使用应用内有界遍历与搜索：逐项 `lstat`，跳过符号链接、受保护目录和凭据文件，限制遍历数量、文件大小、结果量和执行时间；不由 Pi 工具在运行时查找或下载 `rg`、`fd`。首版沿用 Pi 的默认结果上限：`grep` 100 条、`find` 1000 项、`ls` 500 项和 50 KiB 输出上限，并为扫描文件数与单文件大小设置明确硬上限。正则匹配在可终止的 Worker 中执行，超时或取消时终止 Worker，避免模型提供的表达式阻塞主进程；glob 匹配也要有复杂度边界。保留可行的 glob、大小写、上下文和截断参数；无法保留的 `.gitignore` 等可见语义须列入迁移差异并更新工具描述。不能只在 `tool_call` 钩子做路径预检后调用原生工具。
5. **自定义工具清单**：为每个 `slides_*`、`document_read`、`pptx_read`、`download_asset`、Web、Todo 与模板工具维护一条“输入路径/外部资源 → 服务层校验 → 实际 I/O”映射。工具注册可复用现有实现；缺少边界校验的工具在本阶段补齐。新增工具必须更新清单和负向测试。
6. **辅助拒绝钩子**：保留极小的应用内 `tool_call` 钩子，用于对未知/未授权工具及明显错误的资源类型快速拒绝、输出脱敏诊断。钩子本身不是安全边界，不保存用户可编辑策略，也不提供运行时永久授权。

## 实施步骤与停止条件

1. **建立基线**：在临时项目中补充现有扩展的真实工具测试，覆盖项目外路径、项目内指向外部的符号链接、只读 Skill、默认搜索根、项目权限覆盖文件及未知工具。记录当前行为、所需行为与差异。发现可造成越界读写的现实路径时先修复当前保护，再推进迁移。
2. **完成 Pi 核心配置隔离**：按总方案注入内存设置，关闭外部 Skill 和附加提示词发现；验证首次创建、reload、会话恢复和并行会话。该阶段继续加载现有权限扩展，不把核心隔离和权限替换混为一次无回滚边界的改动。
3. **并行接管工具**：先实现文件路径策略和 `read/write/edit`，再处理 `grep/find/ls`；补齐自定义工具审计。迁移期间保留插件且采用两层策略的交集。若插件阻断应用所需的合法行为，先分析差异，不绕开新边界。
4. **切除插件**：通过全部验收后移除 `preparePermissionSystem`、插件加载路径、依赖及第三方声明，更新扩展数量断言、README 和总方案实施记录。保留旧配置与历史会话文件，不迁移或删除用户数据。

如第 3 步无法在当前 Pi 工具接口上安全保留必需行为，停止移除，改用固定版本补丁关闭项目权限合并、旧 settings/MCP 读取和环境变量回退，并对执行路径另加宿主校验。改动分散到不宜维护补丁时再评估 Fork；不 Fork Pi 核心。

## 验收、风险与回滚

- **配置隔离**：在用户目录、项目 `.pi/agent`、旧路径和服务商环境变量注入相反的标记策略，验证没有读取这些禁止的配置路径且工具结果不变；涵盖模块导入、首次创建、reload、恢复和并行会话。
- **工具执行**：以实际注册工具执行覆盖绝对路径、`..`、前缀相似目录、Windows 大小写与分隔符、符号链接目标及父目录、断链、默认搜索根、内置 Skill 只读、未知工具和工具同名覆盖。不能只直接调用 `emitToolCall` 测钩子。
- **业务回归**：验证文字与图片读取、文件编辑和版本事件、搜索结果、Todo、文档读取、演示读写导出、下载、会话恢复与资源重载。记录 `grep/find/ls` 搜索语义变化并更新工具描述。
- **工程门禁**：执行针对性测试、`pnpm test`、Node/Web TypeScript 检查、`pnpm format:check`、开发态与打包后冒烟验证；最终审查 diff 和依赖锁文件。
- **主要风险**：路径检查与实际 I/O 间的竞态、Pi SDK 升级改变工具注册/覆盖语义、搜索工具行为退化、遗漏自定义工具的隐藏 I/O、第三方扩展仍可在主进程自行读写。逐阶段提交和保留旧数据便于回滚；回滚到旧插件版本会重新暴露外部配置读取，须在回滚记录中说明。

本提案满足仓库大范围变更所需的目标、范围、步骤、影响、风险、验证与回滚说明。实施代码前按仓库规则取得明确确认。
