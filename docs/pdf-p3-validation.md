## 方法与环境

- 本机：macOS Darwin 24.6.0、Apple M1 Pro、SlideMind 0.0.0、Electron 44.0.0、Chromium 152.0.7977.54、Electron Node 24.18.1。
- [探针](../scripts/pdf-p3/run-local.mjs)在临时用户数据目录启动生产构建，通过真实 preload、IPC 和主进程服务导出。系统文件对话框由探针指定到隔离样本目录，因此本次没有验收对话框交互。
- `node scripts/pdf-p3/run-local.mjs` 检查未打包生产构建；`node scripts/pdf-p3/run-local.mjs --asar` 使用 macOS arm64 安装包内的 `app.asar`。后者在测试 Electron 外壳中运行，不代表从 DMG 安装后启动。可向 `--asar` 传入其他平台 `app.asar` 路径。
- 探针自动生成中文长 Markdown、PNG/JPEG/单帧 GIF/WebP、30 页原生演示文稿，并检查缺失图片与导出中关闭窗口后不留下 PDF、临时文件或隐藏窗口。产物、样本和包含 SHA-256 的报告位于被忽略的 `.local/pdf-p3/build/` 与 `.local/pdf-p3/asar/`；重复执行会覆盖同名产物。

## P3 发现与修复

1. **高 DPI 导出失败，阻断级**：隐藏窗口报告的 `devicePixelRatio` 与 `capturePage()` 实际像素尺度不一致，第一页超过 1200 万像素上限。现在按真实截图像素校准窗口宽度，并在截图超过目标宽度时缩至 2560 像素。同一 30 页样本复测通过。
2. **生产打印页背景偏蓝，视觉中级**：Vite 把通用样式放在打印页内联规则之后，覆盖了白色背景及部分分页样式。现在打印页规则使用更明确的选择器。复测页面白底，长代码未横向裁切。
3. **Windows 资源路径判断，兼容性中级**：两条 PDF 链路曾用固定的 `/` 匹配 `file:` 路径前缀，在 Windows 上可能拒绝应用内资源。现改用平台路径分隔符；该修复仍需 Windows 安装态实测。
