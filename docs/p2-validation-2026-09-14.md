# 工作区与 PPTist 性能验证记录

记录日期：2026-09-14。保留会话 hooks、渲染测试与 PPTist 快照优化的历史结果；本次文档整理未重新测量。当前验证命令见[开发与验证](development.md)。

## 实施范围

- 将会话元数据的防抖保存、快照去重和卸载保存抽到 `use-conversation-persistence`；会话加载与界面状态仍由工作区管理。
- 将 Agent 文本增量、活动和待办事件订阅及卸载清理抽到 `use-agent-events`，继续按原始 conversationId/requestId 路由，保留完成响应之前 flush 的顺序。工作区减少 79 行，未进行整体重构。
- 新增独立渲染测试入口（现由 `pnpm test` 调用）：使用已有 Electron、Vite 和 React/Vue 依赖，在临时用户目录运行可见测试窗口。项目 IPC 和 Agent API 使用符合共享类型的测试替身；不会读写真实项目或调用模型。
- 新增 `serializePptistPresentation`，仅在快照阶段对 theme/slides 使用 Vue `toRaw`，减少不必要的代理遍历；深度监听仍负责跟踪编辑。加载比较直接使用序列化结果，省去此前的一次 JSON.parse 和一次 JSON.stringify。
- 同步仍发送完整演示文稿对象，保留 120 ms 防抖。主进程、preload、revision 持久化事务、PPTX 导出契约均未修改。

## 行为验证

当时的综合检查：43 个测试文件、205 项测试通过，包含 PPTist/Vue 类型检查和新增的快照等价性测试。

当时的渲染测试：以下 7 组检查通过，未记录浏览器 console error：

1. 持久化 hook：未完成加载时禁止保存、防抖、相同快照不重复写入、保存失败与恢复、卸载时保存最新状态。
2. React 工作区和真实 CodeMirror：编辑文档、保存、关闭并重新打开。
3. 保存 revision 冲突和外部变更通知：保留本地未保存内容，不覆盖外部内容；重新载入读取外部版本。
4. Agent 生成中切换会话：增量留在原始会话，切回后可见，完成内容正确；持久化仅保存会话元数据。
5. 卸载时取消文本、活动、待办订阅。
6. 真实 React ↔ Vue/PPTist iframe：加载、修改 Vue store、变化消息到达 React，以及保存快捷键到达宿主。
7. 真实 PPTist 画布：中英文文字和图片加载断言；截图人工确认文字、强调、蓝色字体与图片显示，无明显重叠或裁切。

这属于渲染层集成验证：项目磁盘和 preload/IPC 未纳入本次浏览器测试，不等同于完整桌面端到端测试。视觉样例仅覆盖基础文本与图片，不代表任意复杂页面或 Office 兼容性通过。

`pnpm exec electron-vite build`：主进程、preload 和渲染进程生产构建通过。构建输出仅有第三方 chokidar 的未使用导入警告。

## 大文稿测量

运行环境：Apple M1 Pro，macOS Darwin 24.6.0 / arm64，Electron 44.0.0，Chromium 152.0.7977.54；测试窗口 1440 × 1000。

每组预热 1 次，采样 20 次。样例每页两个文本元素，有图组额外包含一张确定性生成的 PNG 图片；图片以 data URL 内嵌并在每页重复。MB 为完整文稿 UTF-8 JSON 的十进制体积，不是图片解码内存。

每次在真实 PPTist store 修改首个文本元素，分别等待 Vue nextTick、requestAnimationFrame 和宿主 change 消息。消息同步完成后才执行快照性能探针，避免额外序列化污染本次编辑帧延迟。原实现与优化实现交替调整测量先后顺序，并逐次检查结果等价。快照耗时包含 JSON.stringify 与 JSON.parse，保持与生产快照路径一致。

200 页大图片组的快照 P50 从 31.8 ms 降至 21.3 ms，约减少 33%。200 页无图组从 5.0 ms 降至 0.9 ms。小样例并非稳定改善：50 页小图组从 3.4 ms 到 3.6 ms；不据此承诺所有文稿等比例提速。

编辑帧回调指标不是屏幕实际呈现完成时间，也不包含稍后防抖回调的全量序列化阻塞。同步耗时包含现有 120 ms 防抖和宿主消息事件到达，未包含 React 后续所有渲染工作。表中同步结果来自优化后的实现，不作为优化前后端到端对比。

这些结果支持先落地范围较小的代理遍历与重复序列化优化；尚不足以支持引入增量消息协议。大图片快照仍可占用超过一帧的主线程时间，后续若优化图片存储或消息协议，应另行制定兼容与事务验证方案。未设置跨机器绝对性能阈值。

## 复现与产物

```bash
pnpm exec tsc --noEmit -p tsconfig.node.json
pnpm exec tsc --noEmit -p tsconfig.web.json
node scripts/typecheck-pptist.cjs
pnpm test
pnpm exec electron-vite build
```

测试会临时打开 Electron 窗口，仅监听本机服务，并在退出时清理临时用户目录。曾观察到隐藏窗口长时间停顿，最终验收使用可见窗口；早期超时结果不计入表格。进程具有 180 秒外部看门狗，避免挂起后遗留测试实例。

运行产物写入 `.local/renderer-tests/results.json` 和 `.local/renderer-tests/pptist.png`，未提交生成文件。失败返回非零退出码，能完成页面捕获的断言失败另存 `failure.png`。性能结果会随机器和负载变化，应以同轮原实现/优化实现对比判断。
