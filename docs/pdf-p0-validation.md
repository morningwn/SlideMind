# PDF 导出 P0 本机验证

日期：2026-09-16。状态：macOS arm64 开发态结构探针与当前样本视觉复核已完成；跨平台、安装态及扩展样本待验证。

## 环境与复现

- macOS Darwin 24.6.0、Apple M1 Pro、Electron 44.0.0、Chromium 152.0.7977.54、Electron Node 24.18.1。
- PDFKit 0.17.2 仅临时安装在仓库外，尚未加入产品依赖或打包。探针使用当前 PPTist 渲染页面、当前 Markdown 预览 CSS、`marked`、DOMPurify 和 Electron `printToPDF()`。
- 探针：[脚本](../scripts/pdf-p0/run-probe.mjs)、[Markdown 样本](../scripts/pdf-p0/markdown.html)。本机运行：先在仓库外安装 PDFKit，再设置 `PDFKIT_PROBE_PATH` 为其 `pdfkit` 包目录，执行 `node scripts/pdf-p0/run-probe.mjs`。产物和完整 SHA-256、耗时记录在被忽略的 `.local/pdf-p0/report.json`。探针会覆盖该目录下同名样本产物。

## 实测结果

| 样本                 |    PDF 大小 |                   耗时 | 主进程 RSS 峰值 | 结构                   |
| -------------------- | ----------: | ---------------------: | --------------: | ---------------------- |
| Markdown A4，5 页    |   174,293 B |         433 ms（打印） |            未测 | `pdfinfo` 确认 5 页 A4 |
| PPT 1280 窗口，1 页  |    25,468 B | 2,871 ms（含首次加载） |          134 MB | 960 × 540 pt           |
| PPT 1920 窗口，1 页  |    39,435 B |                 536 ms |          155 MB | 960 × 540 pt           |
| PPT 2560 窗口，1 页  |    53,578 B |                 482 ms |          167 MB | 960 × 540 pt           |
| PPT 1920 窗口，10 页 |   392,407 B |                 875 ms |          212 MB | 10 页，均为 16:9       |
| PPT 1920 窗口，30 页 | 1,184,051 B |               1,692 ms |          279 MB | 30 页，均为 16:9       |

表格为一次实测；重复运行的耗时和 RSS 会波动，最新值见 `.local/pdf-p0/report.json`。报告的结构检查可自动运行，视觉结果仍需逐页人工复核。

固定 `.slides.json` 样本的最新运行中，显示缩放与 `devicePixelRatio` 均为 1，1280、1920、2560 窗口分别生成 1280 × 720、1920 × 1080、2560 × 1440 PNG，约为 96、144、192 dpi。此前同机运行观测到 2 倍实际像素输出；该差异目前没有定位为显示配置变化还是运行环境变化。单页清晰度与尺寸增长相符；P1 暂以**实际截图宽约 2560 像素**为默认目标，并以测得的 PNG 像素为准，而不是直接固定窗口宽度。

在 1920 窗口样本中，PDF 第 1 页按 144 dpi 还原后为 1920 × 1080；与原始 PNG 的逐像素 RGB 平均绝对差为 0.4828、0.4088、0.2304（每通道满量程 255）。差异主要位于文字、形状及图表边缘；已目视核对 PDF 中的中文、背景、叠放、半透明形状、图片与图表。该数值只说明当前样本的 PDF 嵌入链路接近原始截图，不证明所有 PPTist 元素均正确。

Markdown 样本包含中文、三级标题、嵌套列表、16 行长表、28 行长代码、PNG/JPEG/静态 GIF/WebP 和跨页段落。视觉核对 5 页：表格与长链接换行，代码未横向裁切，图片顺序正确。初次打印在末页正文之后出现大块浅色背景；原因是复用的全局样式为 `:root` 设置了浅色背景，而打印页只覆盖了 `body`。打印页同时将 `:root` 设为白色后，复核末页与跨页代码均正常。P1 专用打印窗口必须显式覆盖根元素背景，并保留此长文档回归样本。

图片解码失败时，探针在 `printToPDF()` 前中止。PDFKit Buffer 图片嵌入与 Node 流写入成功；取消流后删除了临时文件；排他创建 `wx` 拒绝覆盖已有文件并保留原内容。这些只是探针层验证，尚未测试产品的保存对话框、目标变化复核与 IPC 生命周期。

## P0 尚未通过的门禁

- GIF 样本为单帧。动画 GIF 的静态帧选择尚未证明可复现；P1 应固定首帧并验证，或识别动画后明确报错。
- 当前打印样式仅为探针；P1 需要将根元素背景、分页规则、资源授权和安全配置纳入正式打印服务并重新验收。
- PPT 样本覆盖文字、背景、形状透明度、图片和图表，但仍缺真实用户 `.slides.json`、异常元素、字体替换、视频静态帧及高复杂度页面。30 页样本重复同一页面结构，不能代表长演示文稿的最坏内存。
- 主进程 RSS 随页数增长；当前探针未记录 Electron 渲染子进程和系统总峰值。逐页提供 PNG 不意味着 PDFKit 内部缓存恒定。P1 必须限制页数和内存，并对复杂图片进行重新测量。
- 探针页面通过本地 Vite 开发服务器加载，不代表受限产品打印窗口；资源授权、请求拦截、关闭窗口与应用退出清理尚待 P1 验证。
- macOS x64、Windows x64、三个平台安装包的离线导出、中文路径、实际打印和 PDF 视觉审查均待验证。当前结论仅适用于本机 macOS arm64 开发态。

后续实现范围仍以 [PDF 导出方案](pdf-export-plan.md) 的 P1/P2/P3 为准。本记录没有开启产品 PDF 入口。
